# planilha_importada_excel

A customer spreadsheet (`clientes_planilha`, 1208 rows) loaded column for column into text, the
way an import wizard does it: every column is a string, there is no key, and the column names are
the sheet's header (`Nome`, `CPF`, `Celular`, `E-mail`, `Data Nasc`, `Valor Compras`,
`Qtd Pedidos`, `Cidade`, `UF`, `CEP`, `Observação`). Generated by `planilha_importada_excel` in
the legacy pack; `preview.json` shows the first rows.

What a spreadsheet does to data:

- **Leading apostrophes** that force a cell to text: `'327.390.709-69`, `'21962470450`,
  `'01310100`.
- **Number cells**: a CPF or CEP that lost its leading zeros (`97926657140` is fine, `1310100`
  is a CEP), and a long number too wide for its column shown in pt-BR scientific notation,
  `1,19877E+10` — the digits past the sixth are gone for good. A quarter of the phones and a few
  CPFs are like this.
- **Dates** as `dd/mm/yyyy`, as two-digit years, and as serial numbers (`31121` is 1985-03-15).
- **pt-BR money**: `1.234,56`, `R$ 1.234,56`, `1234,56`, `-`; counts typed as `3,0`.
- **Error cells** `#N/D` and `#REF!` in the notes.
- **The header row repeated** twice, where three sheets were pasted one under another.
- **Six blank rows** at the end, every cell an empty string, and empty strings for every missing
  value in between.

The scenario asks that identifiers vanish and that every one of these artefacts comes back as the
same artefact, so a re-import of the sandbox hits the same code paths as the real file. In
particular, an empty string is not a NULL: today the engine re-injects empty cells as sentinel
words the file never held (`na`, `nil`, `undefined`, `none`), and turns a CPF behind an
apostrophe into a malformed CPF with a letter inside.

Open rulings: whether the repeated header rows are kept verbatim, whether order counts are kept,
and the state abbreviation.

Not expressible today: "the repeated header rows are kept" is written on the `Nome` column only,
since an assertion cannot select rows by another column's value.
