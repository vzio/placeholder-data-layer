# chaves_compostas_e_ciclos

An HR schema where the masked CPF text is the key of everything. Generated by
`chaves_compostas_e_ciclos` in the legacy pack; `preview.json` shows the first rows.

| Table | Key | References |
|---|---|---|
| `pessoa` (600) | `cpf` | `gestor_cpf` → `pessoa.cpf` (self-reference; two people name each other as manager, and 8 rows name a former employee); `departamento_id` → `departamento.id` |
| `departamento` (12) | `id` | `responsavel_cpf` → `pessoa.cpf`, closing a cycle with `pessoa.departamento_id` |
| `filial` (16) | `(cod_empresa, cod_filial)` | `gerente_cpf` → `pessoa.cpf` |
| `lotacao` (1186) | `(cpf, cod_empresa, cod_filial, data_inicio)` | each of the first three onto its own column; 6 rows name branch 99, which closed |
| `dependente` (400) | `cpf_dependente` | `cpf_titular` → `pessoa.cpf`; 5 rows name a former employee |
| `ponto_eletronico` (3000) | `id` | none declared: `cpf_funcionario` holds the employee's CPF as bare digits, and joins `pessoa.cpf` only after dropping the mask |

The former employees' CPFs are the same values in `pessoa.gestor_cpf` and
`dependente.cpf_titular`, so orphans must keep their identity across tables too.

**Composite keys.** The wire format marks each member of a composite primary key `pk: true` and
cannot declare a composite foreign key: `lotacao` references `filial` through two independent
single-column edges. The engine accepts the dataset (no `refused` expectation is needed) and mints
each member column on its own. Each member keeping its identity, which holds, implies the tuples
stay distinct. Two things a finished engine should do are written as targets: a date that is a
key member should stay a date (today it is minted into an opaque value, 96% of them impossible
dates), and the time clock's undeclared CPF should stay consistent row to row (today the same
CPF regenerates differently in each row, so an employee's punches no longer group).

Not expressible today, so stated here:

- **Composite referential integrity.** Four assignments name a `(cod_empresa, cod_filial)` pair
  that never existed although both codes exist on their own: orphans at the tuple level that no
  single-column check sees, and that should stay orphans at the same rows.
- **Cross-format key identity.** The time clock's `12345678909` and `pessoa`'s `123.456.789-09`
  are the same person; they should map to the same output CPF, each in its own layout.
  `key_identity` compares typed values, so it cannot express a join on the digits.
- **Tuple identity** of `(cod_empresa, cod_filial)` across `filial` and `lotacao`.

Ruled: clock-in times pass through with their exact distribution.
