# colunas_genericas_eav

Two ways a schema hides what its columns mean. Generated by `colunas_genericas_eav` in the legacy
pack; `preview.json` shows the first rows.

**Entity-attribute-value.** `entidade` (800: customers, suppliers, products) and
`atributo_valor` (4194), one row per attribute: `(entidade_id, atributo, valor)`. The single
`valor` column holds, row by row, customers' names, emails, CPFs (masked and bare), birth dates
(ISO and Brazilian layouts), phones, sales channels and notes that repeat the CPF or phone;
suppliers' legal names, CNPJs, emails, phones and CEPs; products' descriptions, colours, weights
and SKUs. An attribute is missing one time in eight.

**Generic columns.** `cadastro_generico` (1000) with `campo1` to `campo20`:

| Column | Holds |
|---|---|
| `campo1`–`campo6` | name, masked CPF, email, masked phone, birth date `dd/mm/yyyy`, masked CEP |
| `campo7`, `campo8` | city, state |
| `campo9` | status code `A`/`I`/`B` |
| `campo10` | amount as text, `342.68` |
| `campo11` | notes, some repeating the CPF or phone |
| `campo12`, `campo20` | constants `0` and `3` |
| `campo13` | phones in the first half of the rows, emails in the second: reused after a form redesign |
| `campo14` | always NULL |
| `campo15` | empty, or an `X` marker |
| `campo16` | legacy customer code `CLI-000123` |
| `campo17` | last update, ISO date |
| `campo18`, `campo19` | a rare remark; flag `S`/`N` |

The scenario asks that each value be anonymized as what it is, row by row, whatever column it
sits in: CPFs and CNPJs regenerated valid, email domains and CEP regions kept, dates kept as
calendar dates, and the non-personal columns (attribute names, kinds, codes, constants, flags)
kept. Today the whole `valor` column is redacted as free text, so every CPF in it becomes
`00000000000`, and the attribute names are redacted too, which makes the table unreadable.

Open rulings: whether the state passes through, and whether a legacy customer code is kept or
re-minted.

Not expressible today: an assertion over the rows of `valor` whose `atributo` is `nome` (or
`email`, `cor`…). Without a row filter by a sibling column, names and product data in `valor`
cannot be asserted on separately, so only digit runs, check-digit validity, email domains, CEP
regions and date shapes are.
