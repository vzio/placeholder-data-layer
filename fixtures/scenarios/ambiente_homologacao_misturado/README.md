# ambiente_homologacao_misturado

A staging copy of a shop's `usuarios` (1500) and `pedidos` (3000) that QA then wrote into.
Generated by `ambiente_homologacao_misturado` in the legacy pack; `preview.json` shows the first
rows.

| Rows | What they are |
|---|---|
| 1 | The seeded administrator at `id = 1`: `Administrador do Sistema`, `admin@…`, CPF `000.000.000-00`, no phone, role `admin`. It creates 85% of all orders (`pedidos.criado_por`). |
| 45 | Pure test accounts: `Fulano de Tal`, `Beltrano da Silva`, `Teste QA`; `qa+7@mailinator.com`, `teste3@teste.com`, `fulano2@example.com`, `teste+9@gmail.com`; CPFs `999.999.999-99`, `111.111.111-11`, `000.000.000-00` and the two published examples; phones `(00) 00000-0000`, `(11) 99999-9999`. |
| 90 | Real customers with one or two fields overwritten by a tester: a mailinator or yopmail address over their own local part, a `999.999.999-99` or `111.111.111-11` CPF, a `(11) 99999-9999` phone, a `Teste` prefix on their name. |
| 12 | Test accounts in the QA team's own convention: `QA Automação 03`, `qa.automacao03@` the shop's domain, a check-digit-valid generated CPF, `(11) 91234-5603`. No generic placeholder list knows them. |
| 24 | Real customers whose surname merely contains a test word: Testa, Testoni, Admiral, Demo, Fulani, Rootes. They must not be counted. |
| 1327 | Ordinary customers. |

The scenario asks for exact counts — 148 test rows, 90 of them mixed — so over-flagging the
lookalikes fails as surely as missing the house-style accounts, and for the usual privacy,
format and join guarantees around them.

Open rulings: whether rows sharing a test CPF or test phone keep sharing one afterwards, which
keeps test data recognisable as a group at the cost of a linkable pseudonym.

Not expressible today, so stated here:

- **The administrator keeps `id = 1`.** Application code and configuration hard-code it, so a
  sandbox where the admin is id 7364 does not boot. Every key keeps its identity today, but no
  assertion can pin one row's output value.
- **Test rows still read as test rows after anonymization.** Today a `Sicrano de Oliveira` row
  comes out as a realistic name, its `000.000.000-00` as a malformed CPF with a letter inside, and
  the admin's `admin@` local part as random letters: QA data becomes indistinguishable from real
  customers in the sandbox. The non-production counts are only reported for the source.
